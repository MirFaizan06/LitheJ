Files & Directories

UTF-8-by-default file I/O with explicit overwrite semantics, plus directory-level helpers, from lithej-io.

Reading

String text = FileIO.read(path);                 // whole file, UTF-8
String text2 = FileIO.read(path, charset);        // explicit charset
List<String> lines = FileIO.readLines(path);
byte[] bytes = FileIO.readBytes(path);

Writing

Write methods create missing parent directories automatically and overwrite an existing target file — the same behavior as Files.writeString, documented on every method rather than left as a surprise.

FileIO.write(path, "content");
FileIO.writeLines(path, List.of("a", "b", "c"));
FileIO.writeBytes(path, bytes);
FileIO.append(path, "more\n");                    // creates the file if absent
FileIO.writeAtomic(path, "content");               // write-to-temp, then atomic move

Copy & move

Unlike writing, copy/move refuse to overwrite an existing target by default — you opt in explicitly:

FileIO.copy(source, target);            // throws FileAlreadyExistsException if target exists
FileIO.copy(source, target, true);      // explicit opt-in to overwrite
FileIO.move(source, target);
FileIO.move(source, target, true);

Delete, exists, metadata

FileIO.delete(path);                    // throws if missing
FileIO.deleteIfExists(path);            // returns false if missing, never throws for that
FileIO.exists(path);
FileIO.size(path);
FileIO.extension(Path.of("archive.tar.gz"));  // Optional["gz"]
FileIO.name(Path.of("a/b/c.txt"));            // "c.txt"

Walking a tree

List<Path> allFiles = FileIO.walk(root);                       // regular files, recursive
List<Path> txtFiles = FileIO.find(root, p -> p.toString().endsWith(".txt"));

Temp files

Path tempFile = FileIO.tempFile("prefix-", ".tmp");   // deleted on normal JVM exit
Path tempDir = FileIO.tempDirectory("prefix-");        // NOT auto-deleted; clean it up yourself

Directories

Directories.ensureExists(dir);              // create if missing, no-op if already a directory
Directories.create(dir);                    // create (including parents)
List<Path> children = Directories.list(dir);           // immediate children only
List<Path> all = Directories.listRecursive(dir);        // every descendant
long bytes = Directories.size(dir);                     // recursive total
boolean empty = Directories.isEmpty(dir);
Directories.copyTree(source, target);        // target must not exist, or must be empty
Destructive, on purpose: 
Directories.empty(dir);            // deletes every entry inside dir, keeps dir itself
Directories.deleteRecursive(dir);  // deletes dir and everything inside it
Both permanently destroy data with no recovery mechanism. Their names say exactly what they do — there is no shorter alias for either, on purpose. Never call either with a caller-controlled path you haven't validated.

Classpath resources

For files bundled inside your JAR (not on the real filesystem), use Resources instead of FileIO — see Configuration & Resources.
