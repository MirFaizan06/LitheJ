Migration & Compatibility

Versioning policy

LitheJ follows Semantic Versioning. Before 1.0.0, minor versions may include breaking changes as the API is finalized. From 1.0.0 onward, only major version bumps break public API compatibility. This is checked automatically via Revapi in CI once a 1.0.0 baseline exists.

Upgrading between versions

See CHANGELOG.md for the full history. Each release entry lists additions, changes, and (for major versions) breaking changes with a migration note.

Migrating from hand-written Java

LitheJ methods accept and return standard JDK types, so adoption is usually a local, incremental replacement — you don't need to migrate a whole codebase at once:

BeforeAfter
BufferedReader reader = new BufferedReader(
    new InputStreamReader(System.in));
System.out.print("Enter age: ");
int age;
while (true) {
    try {
        age = Integer.parseInt(reader.readLine());
        break;
    } catch (NumberFormatException e) {
        System.out.println("Invalid.");
    }
}
 
int age = Console.askInt("Enter age: ");
 
List<String> lines = Files.readAllLines(
    Path.of("users.txt"), StandardCharsets.UTF_8);
 
List<String> lines = FileIO.readLines(
    Path.of("users.txt"));

FAQ

Does LitheJ replace java.util.stream?

No. LitheJ's collection helpers exist for the specific cases where a stream pipeline is noticeably more boilerplate than a single named method (e.g. Lists.groupBy vs. Collectors.groupingBy plus imports). Where a stream is already simple, use a stream.

Can I mix LitheJ with plain Java?

Yes, freely — that's the point. Every method takes and returns standard JDK types, so you can call LitheJ for one line and plain Java for the next with no friction.

Is LitheJ thread-safe?

See the README's thread-safety section and each class's own Javadoc. In short: stateless utility classes and immutable value types are thread-safe; ConsoleIO is not, for concurrent reads.

Why doesn't Http support retries or connection pooling config directly?

Because that's exactly the kind of scope that turns a thin wrapper into a competing framework. Supply your own pre-configured HttpClient via HttpOptions.withClient(...) for anything beyond a single request/response.

Where do I report a bug or request a feature?

GitHub Issues. See SUPPORT.md in the repository.
