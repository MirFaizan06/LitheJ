Processes

A safe wrapper around ProcessBuilder, from lithej.process.ProcessX in lithej-io.

Running a command

ProcessResult result = ProcessX.run("git", "status");
ProcessResult result2 = ProcessX.run(List.of("git", "status"));

result.exitCode();
result.succeeded();     // exitCode() == 0
result.stdout();
result.stderr();

Options

ProcessOptions options = ProcessOptions.defaults()
        .withWorkingDirectory(Path.of("/tmp/build"))
        .withEnvironment(Map.of("CI", "true"))     // added on top of the inherited environment
        .withTimeout(Duration.ofSeconds(30));

ProcessResult result = ProcessX.run(List.of("./build.sh"), options);
Why not just use ProcessBuilder directly? ProcessX always drains stdout and stderr on dedicated threads while waiting for the process to exit. This avoids a classic deadlock: if a process writes more output than the OS pipe buffer holds (typically 64KB) and nothing is reading it, the process blocks trying to write, and code that waits for exit before reading output blocks forever.

Timeouts & failures

If a timeout is configured and elapses, the process is forcibly terminated (destroyForcibly()) before ProcessTimeoutException is thrown. If the process cannot be started at all (e.g. the command doesn't exist), or the calling thread is interrupted while waiting, ProcessExecutionException is thrown (with the interrupt flag restored first, in the interruption case).

Quoting

Each element of the command list is passed to the OS as a separate argument — there is no shell involved unless you explicitly invoke one (e.g. List.of("sh", "-c", "...")). You do not need to quote arguments containing spaces yourself.
