Date & Time

lithej.time.Times is a thin set of conveniences built directly on java.time — not a competing date/time framework. Every method accepts and returns standard java.time types.

Timezone discipline is the core design rule here: any method that renders "the current moment" as a calendar date/time takes an explicit ZoneId. The one documented exception is Times.today(), which uses ZoneId.systemDefault() because "today" inherently means "today where I am" — and its Javadoc says so in bold, pointing at the zoned overload.

Now & today

Instant now = Times.now();                    // zone-independent
LocalDate today = Times.today();               // uses the system default zone — see above
LocalDate todayUtc = Times.today(ZoneOffset.UTC);
LocalDateTime nowInTokyo = Times.nowAt(ZoneId.of("Asia/Tokyo"));

Parsing & formatting

LocalDate date = Times.parseDate("2026-01-15", DateTimeFormatter.ISO_LOCAL_DATE);
LocalDateTime dt = Times.parseDateTime(text, formatter);
String formatted = Times.format(date, formatter);   // propagates DateTimeParseException on bad input

Comparisons & durations

long days = Times.daysBetween(start, end);      // negative if end is before start
Duration elapsed = Times.between(startInstant, endInstant);

int years = Times.age(birthDate, LocalDate.of(2026, 6, 1));   // throws IAE if asOf precedes birthDate
int yearsToday = Times.age(birthDate, ZoneId.systemDefault());

boolean past = Times.isPast(someInstant);
boolean future = Times.isFuture(someInstant);
boolean pastDate = Times.isPast(someDate, zone);
boolean futureDate = Times.isFuture(someDate, zone);

Calendar helpers

Times.isWeekend(date);    // Saturday/Sunday (ISO/Western convention — documented, not locale-aware)
Times.isWeekday(date);
Times.atZone(instant, zone);
