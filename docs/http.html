HTTP

A thin wrapper around java.net.http.HttpClient for the common case, from lithej-net. Not a competing networking framework — no retries, cookie jars, or auth flows built in.

Requests

HttpResponse get = Http.get(url);
HttpResponse post = Http.post(url, body);
HttpResponse put = Http.put(url, body);
HttpResponse del = Http.delete(url);

Options

HttpOptions is immutable; each withX call returns a new instance.

HttpOptions options = HttpOptions.defaults()
        .withHeader("Authorization", "Bearer " + token)   // repeated calls: last value wins
        .withHeaders(Map.of("Accept", "application/json"))
        .withQueryParam("verbose", "true")                 // percent-encoded automatically
        .withTimeout(Duration.ofSeconds(10))
        .withClient(myOwnHttpClient);                       // bring your own HttpClient

HttpResponse response = Http.post(url, body, options);

When no HttpClient is supplied, Http uses a single lazily-created shared default client (10s connect timeout, HttpClient.Redirect.NORMAL). Supply your own via withClient(...) for connection pooling across calls, a custom SSLContext, proxy configuration, or a stricter redirect policy.

Reading the response

response.statusCode();
response.isSuccessful();                 // true for [200, 300)
response.headers();                      // Map<String, List<String>>
response.body();                         // UTF-8 decoded
response.bodyBytes();                    // raw, defensively copied
response.raw();                          // escape hatch: java.net.http.HttpResponse<byte[]>

A non-2xx status (404, 500, ...) is not an exception — it's a normal HttpResponse with isSuccessful() == false. Http throws HttpRequestException only for genuine transport failures: connection refused, timeout, DNS failure, or the calling thread being interrupted. A malformed URL throws IllegalArgumentException instead (a caller bug, not a network failure).

Secret redaction: HttpOptions and HttpResponse redact values for header names that look like secrets (containing authorization, cookie, token, secret, key, or password, case-insensitive) in their toString() output. This is a best-effort heuristic, not a guarantee — see SECURITY.md.
