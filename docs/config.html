Configuration & Resources

Environment variables, .properties files, a small layered config source, and classpath resource access, from lithej-config (and lithej.io.Resources for the last one).

Env

Optional<String> home = Env.get("HOME");
String required = Env.require("DATABASE_URL");       // throws NoSuchElementException if unset
int port = Env.getInt("PORT", 8080);
boolean debug = Env.getBoolean("DEBUG", false);       // recognizes true/1/yes/y, false/0/no/n

Env is read-only — environment variables can't be changed at runtime, so there is no Env.set(...).

PropertiesX

Properties props = PropertiesX.load(path);                       // UTF-8 by default
Properties props2 = PropertiesX.load(path, charset);
Properties props3 = PropertiesX.loadFromResource("app.properties"); // from the classpath

String value = PropertiesX.require(props, "app.name");
int port = PropertiesX.getInt(props, "port", 8080);
boolean flag = PropertiesX.getBoolean(props, "enabled", false);

Config — layered, explicit precedence

Layers are consulted in the order they were added; the first layer that has a value wins. List higher-priority overrides first:

Config config = Config.empty()
        .withSystemProperties()       // -Dport=8080 on the java command line
        .withEnvironmentVariables()   // PORT=8080 in the shell
        .withProperties(fileProps)    // port=8080 in app.properties
        .withDefault("port", "8080"); // final fallback

int port = config.getInt("port", 8080);
String name = config.require("app.name");

Resources (classpath)

For files bundled inside your JAR, not on the real filesystem:

String config = Resources.read("config/defaults.properties");
List<String> lines = Resources.readLines("data.csv");
byte[] bytes = Resources.readBytes("logo.png");
boolean present = Resources.exists("optional.txt");
try (InputStream in = Resources.open("large-file.bin")) { ... }

Throws ResourceNotFoundException (not a confusing NullPointerException from a null stream) when the resource is missing.
